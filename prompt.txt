在现有 rpa 骨架上，把它做成一个能扛住会话、CSRF、幂等与限流的批量表单录入器。保留 Recorder 的方法签名，只用 Python 标准库，不得引入第三方依赖，不得修改 mock_server.py 的行为。

## 需要完成

1. **会话与 CSRF**
   - 先 GET /form/<id> 拿到 sid cookie 与页面里的 csrf token，再带着两者 POST /submit。
   - 服务端每 5 次提交会让会话失效，收到 403 时要自动重新取表单、换新 token 后重试同一行，不能靠重跑整个批次。
   - 403 重试要有上限，超过上限记为失败并记录原因。

2. **幂等**
   - 重复业务主键的提交服务端会返回 409，本地要在提交前先按 biz_id 去重，只提交一次。
   - 如果上一次运行已经提交成功过（落库记录里存在），本次直接跳过，不重复提交。

3. **数据校验前置**
   - 提交前做本地校验：必填字段为空、字段超长、枚举值不在允许集合、数值字段非法，都要在本地拦下并记入 rejected，不能把脏数据发给服务端。
   - 允许集合与长度限制从配置文件读取。

4. **吞吐与恢复**
   - 支持并发提交，并发度可配置，默认 1；并发时会话与 token 要按连接隔离，不能串用。
   - 支持限速（每秒最多 N 次提交）。
   - 断点续跑：每行的结果落 SQLite（biz_id、status、attempts、last_error），中断后重启跳过已成功的行。

5. **报告**
   - 结束时输出：total、submitted、duplicate_skipped、rejected、failed、retried 六项计数，以及失败行的 biz_id 与原因。
   - 退出码：全部成功 0，存在失败或被拒 1，配置错误 2。

6. **测试**
   - 用进程内的 mock_server 覆盖：取 token 后提交成功、会话失效后自动恢复、409 去重、本地校验拦截、断点续跑。
   - `python -m pytest tests -q` 全部通过。
